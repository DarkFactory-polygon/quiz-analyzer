# Дизайн: quiz-analyzer

CLI на Python, который читает CSV с результатами квиза и печатает в stdout
таблицу доли верных ответов по вопросам и список самых трудных вопросов.
Обслуживает цель G-01.

## Устройство

### Файлы проекта

```
quiz-analyzer/
  pyproject.toml          # метаданные, console_scripts = quiz-analyzer
  quiz_analyzer/
    __init__.py
    __main__.py           # python -m quiz_analyzer -> cli.main()
    cli.py                # разбор аргументов, код выхода, stderr
    reader.py             # чтение и валидация CSV
    stats.py              # агрегация по вопросам, отбор трудных
    report.py             # форматирование текста для stdout
  tests/
    test_reader.py
    test_stats.py
    test_cli.py           # сквозные проверки на критериях приёмки
```

### Команда

```
quiz-analyzer <path.csv> [--threshold <N>]
```

- `<path.csv>` — обязательный позиционный аргумент, путь к файлу результатов.
- `--threshold N` — порог «трудности» в процентах, по умолчанию `50`.
- Эквивалентный вызов без установки: `python -m quiz_analyzer <path.csv>`.
- Код выхода: `0` — отчёт напечатан; ненулевой — ошибка чтения/валидации.

### Данные и поток вызовов

Данные только входные: один CSV-файл, UTF-8, разделитель-запятая, первая
строка — заголовок `student,question,answer,correct`, где `correct` ∈ {`1`,`0`}.
На диск ничего не пишется, отчёт идёт в stdout, ошибки — в stderr.

```
cli.main(argv)
  args = argparse  ->  (path, threshold)
  rows = reader.read_rows(path)            # list[Row] или ValidationError
  table = stats.per_question(rows)          # [QuestionStat] в порядке появления
  hard  = stats.hardest(table, threshold)   # отсортированный список
  print(report.render(table, hard, threshold))
  return 0
```

Структуры в памяти:

- `Row = (student: str, question: str, answer: str, correct: bool)`.
- `QuestionStat = (question: str, correct: int, total: int, share: float)`,
  где `share = 100 * correct / total`; порядок элементов — порядок первого
  появления вопроса в CSV (используется `dict`, сохраняющий порядок вставки).
- `ValidationError(line_no: int, message: str)` — ошибка с номером строки
  исходного файла (как его видит человек в редакторе, заголовок = строка 1).

### Пример вывода

```
Вопрос  Доля верных  Счёт
Q1            80.0%  (8/10)
Q2            30.0%  (3/10)
Q3            45.0%  (9/20)

Самые трудные вопросы (ниже 50%):
  1. Q2 — 30.0% (3/10)
  2. Q3 — 45.0% (9/20)
```

## Решения

#### D-01: Один Python-пакет на стандартной библиотеке, без зависимостей
Проект — пакет `quiz_analyzer` из четырёх модулей (`cli`, `reader`, `stats`,
`report`), использующий только `argparse`, `csv`, `sys`. Внешних библиотек нет:
задача целиком покрывается stdlib, а отсутствие зависимостей убирает установку
и несовместимости у коллег. Разделение на модули нужно, чтобы критерии приёмки
проверялись юнит-тестами без запуска процесса.
**Функции:** FR-01, FR-02, FR-03

#### D-02: Единственная команда `quiz-analyzer <path.csv>` через argparse
Интерфейс — одна команда с обязательным позиционным путём к файлу и опцией
`--threshold`; подкоманд нет. Это ровно то, что названо в критериях приёмки, и
не требует от пользователя помнить флаги. `argparse` даёт `--help` и ошибку с
ненулевым кодом на неверные аргументы бесплатно.
**Функции:** FR-01, FR-02, FR-03

#### D-03: Чтение CSV через `csv.DictReader` с явной кодировкой UTF-8
`reader.read_rows` открывает файл как `open(path, newline="", encoding="utf-8")`
и читает `csv.DictReader` с запятой-разделителем, ожидая заголовок
`student,question,answer,correct`. Кодировка задаётся явно, а не берётся из
локали, иначе файл с кириллицей читался бы по-разному на разных машинах.
Отсутствующий или нечитаемый файл — сообщение в stderr и ненулевой код.
**Функции:** FR-01

#### D-04: Вся валидация до печати; ошибка — stderr + номер строки + код 1
`read_rows` сначала полностью разбирает файл и собирает строки в память, и
только после успешного разбора `cli` печатает отчёт. Если в строке не хватает
полей или `correct` не `1` и не `0`, поднимается `ValidationError` с номером
строки файла; `cli` печатает `results.csv:7: поле correct должно быть 1 или 0,
получено "yes"` в stderr и возвращает код `1`, в stdout не печатая ничего.
Такой порядок — единственный способ выполнить критерий «отчёт в stdout не
печатается»: частично напечатанный отчёт уже не отменить.
**Функции:** FR-01

#### D-05: Агрегация в один проход, порядок вопросов — порядок появления
`stats.per_question` идёт по строкам один раз и копит счётчики в `dict`
`question -> (correct, total)`; так как `dict` в Python сохраняет порядок
вставки, порядок вопросов в таблице автоматически равен порядку их первого
появления в CSV, как требует критерий. Доля считается как
`100 * correct / total` в `float` и печатается с одним знаком после запятой
(`8/10 -> 80.0%`).
**Функции:** FR-02

#### D-06: Трудные вопросы — строго ниже порога, сортировка по возрастанию доли
`stats.hardest(table, threshold)` оставляет вопросы с `share < threshold` и
сортирует их по `share` по возрастанию (сначала худший). Сравнение строгое,
поэтому вопрос с долей ровно `50.0` при пороге по умолчанию `50` в список не
попадает; при `--threshold 40` из долей 80/30/45 остаётся только `Q2`.
**Функции:** FR-03

#### D-07: `--threshold` — число процентов, по умолчанию 50, с проверкой диапазона
Опция принимается как `float` в процентах (а не доля 0..1), чтобы `--threshold
40` из критерия приёмки означало 40%. Значение по умолчанию `50` задано в
`argparse`. Значение вне `[0, 100]` — ошибка аргумента: сообщение в stderr и
ненулевой код, отчёт не печатается.
**Функции:** FR-03

#### D-08: Отчёт — простой текст в stdout, двумя блоками
`report.render` возвращает одну строку: сначала таблица «вопрос / доля / счёт»
с выравниванием по ширине колонок, затем блок «Самые трудные вопросы» с
указанием действующего порога. Формат — plain text без цвета и без таблиц
сторонних библиотек: вывод читается в терминале и нормально переживает
`| grep` и перенаправление в файл. Доля печатается и в таблице, и в списке в
одном формате `NN.N%`, счёт — как `(8/10)`.
**Функции:** FR-02, FR-03

#### D-09: Платформа — Python 3.11+, одинаково на macOS, Linux, Windows
Поддерживаются три платформы брифа; переносимость обеспечивается тем, что в
коде нет ничего платформенного: пути принимаются как строки и передаются в
`pathlib.Path`/`open`, перевод строк в CSV отдан `newline=""` + модулю `csv`
(поэтому файлы с `\r\n` из Excel читаются одинаково), вывод — через `print` с
`\n`. Нижняя граница 3.11 — чтобы не тащить совместимость со старыми версиями;
это первая версия, которую коллеги получают из любого свежего установщика.
**Функции:** FR-01, FR-02, FR-03

#### D-10: Без сети, без авторизации, без записи на диск и без состояния
Процесс не открывает сокетов, не обращается к сети и не имеет понятия
«пользователь»: пользователи — я и коллеги на своих машинах, авторизации в
брифе нет, поэтому прав доступа и конфигов аккаунтов в коде нет. Единственный
побочный эффект — запись в stdout/stderr; файлов, кэша, логов и настроек
программа не создаёт, так что запуск на чужой машине ничего там не оставляет.
Файл результатов открывается только на чтение.
**Функции:** FR-01, FR-02, FR-03

#### D-11: Распространение — копия репозитория, запуск через `python -m` или pip
Коллеги получают проект копией каталога (git clone или архив). Запуск либо
`python -m quiz_analyzer results.csv` без установки, либо
`pip install -e .` — тогда `pyproject.toml` создаёт команду `quiz-analyzer` из
критерия приёмки. Пакета в PyPI и сборки бинарников нет: это личный инструмент
для нескольких человек, которым проще и так.
**Функции:** FR-01

## Открытые вопросы

Пробелы брифа, которые дизайн не закрывает; до ответа поведение в этих случаях
не зафиксировано ни в коде, ни в тестах:

- Что печатать, если трудных вопросов нет (пустой блок, строка вида «трудных
  вопросов нет», или вообще не печатать второй блок) — влияет на `report.render`
  (D-08).
- Порядок в списке трудных при равной доле (по порядку появления в CSV,
  по имени вопроса, по числу ответов) — влияет на ключ сортировки в
  `stats.hardest` (D-06).
